Quickstart

From nothing to a protected program in about ten minutes.

  1. Create an accountSign up at sovyx.cc/login with email or Discord. The Free plan needs no card.
  2. Create an applicationIn your dashboard open Applications and click New application. Each product you sell is its own application. Your App ID is shown in the Applications list.
  3. Create licensesOpen Licenses and click Create licenses. Choose how many, how long (1 day to lifetime) and an optional prefix. The clock only starts on a key's first use.
  4. Add the sign-in call to your softwareSend the buyer's key and the PC's ID to /api/v1/login. Copy-paste examples are below.
  5. Publish a download pageOpen Customer page, pick an address, upload your loader and share the link. Buyers enter their key and the download starts.

Concepts

Applications

An application is one product. It has its own licenses, users, sessions, variables, blacklist and customer page. The App ID is public: you put it in your software. Never put your app secret or seller key in anything you ship.

Licenses

A license is a key such as NEB-7F3K-Q9XW-2MDP. It is unused until someone signs in or downloads with it, then used. A banned key is refused everywhere. Length runs from 1 day to lifetime, and the countdown starts on first use. You can ban, unban, delete and export keys as CSV from the Licenses page.

HWID lock

When HWID lock is on (Settings, per application) the first login binds the key to the HWID your software sends. Any other HWID is refused until the lock is reset. It can be reset three ways:

  • You, from the Licenses or Users page.
  • Buyers, from your customer page or the API. You choose whether it is allowed and how many days they must wait between resets (0 to 365).
  • Staff you have given a panel with the manage permission.
Your software chooses the HWID. Sovyx treats it as an opaque string of 8 to 200 characters, so use something stable for the PC, such as a hash of hardware identifiers. Because it comes from the client, a determined user can fake one. Treat the lock as a strong deterrent, not a guarantee.

Sessions

A successful login opens a session. There is one session per key: signing in again replaces the old one. Your software pings /heartbeat every 30 seconds. A session quiet for over a minute shows as stale. If you end a session, ban the key or the key expires, the next heartbeat fails and your software should close.

Variables and blacklist

Variables (Pro) are name and value pairs you set in the dashboard. Every login returns them in variables, so you can change a message or setting without shipping a new build. The blacklist (Pro) blocks IP addresses and HWIDs: their logins are refused with a 403.

Webhooks (Pro) can tell your own server when a key is redeemed, someone signs in or a sign-in is blocked. See Webhooks.

Sign-in API

Your software talks to Sovyx with four JSON requests. Every request is a POST with Content-Type: application/json. No secret is needed in the client: the App ID is public.

Base URL: https://sovyx-site-production.up.railway.app. Your dashboard's API keys page always shows the current address.

POST /api/v1/login

POST/api/v1/login

Signs a key in. On the first login it starts the key's countdown and locks it to the PC. Opens a live session.

POST /api/v1/heartbeat

POST/api/v1/heartbeat

Keeps the session alive. Call it every heartbeatSeconds.

FieldType
appIdstringRequired.
sessionstringFrom login. Required.
{ "ok": true }

A 401 means the session ended. A 403 means the key was banned, removed or expired. Close your program in both cases.

POST /api/v1/logout

POST/api/v1/logout

Ends the session. Safe to call twice.

POST /api/v1/hwid-reset

POST/api/v1/hwid-reset

Unlocks a key from its PC so it can sign in on a new one. Also ends its session. Follows your cooldown setting.

FieldType
appIdstringRequired.
keystringThe buyer's key. Required.
{ "ok": true, "cooldownDays": 7 }

Errors and limits

Errors are JSON like { "error": "That key isn't valid." }.

StatusMeaning
200It worked.
400A field is missing or invalid.
401The key isn't valid, or the session has ended.
403The key is banned or expired, the IP or HWID is blacklisted, the key is locked to another PC, or the action is turned off.
404Unknown application.
409Nothing to reset: the key isn't locked to a PC yet.
429Too many attempts, or the reset cooldown hasn't passed. Logins and resets are limited to 30 per IP every 5 minutes.
503Down for maintenance, or the product isn't set up yet.

Code examples

These show the whole flow: sign in, heartbeat on a timer, sign out. Pick your language.

import hashlib, os, platform, threading, time, uuid
import requests

API = "https://sovyx-site-production.up.railway.app"
APP_ID = "YOUR_APP_ID"          # from the Applications page


def hwid() -> str:
    # Any stable string for this PC, 8-200 characters.
    return hashlib.sha256((str(uuid.getnode()) + platform.node()).encode()).hexdigest()


def post(path, body):
    r = requests.post(API + path, json=body, timeout=10)
    return r.status_code, r.json()


key = input("Key: ").strip()
code, info = post("/api/v1/login", {"appId": APP_ID, "key": key, "hwid": hwid(), "version": "1.0.0"})
if code != 200:
    raise SystemExit(info["error"])              # wrong key, banned, expired, other PC...
print(f"Signed in. {info['daysLeft']} days left.")


def keep_alive():
    while True:
        time.sleep(info["heartbeatSeconds"])
        code, reply = post("/api/v1/heartbeat", {"appId": APP_ID, "session": info["session"]})
        if code != 200:                          # session ended, key banned or expired
            print(reply["error"])
            os._exit(1)


threading.Thread(target=keep_alive, daemon=True).start()

// libcurl + nlohmann/json
#include <curl/curl.h>
#include <nlohmann/json.hpp>
#include <string>
using json = nlohmann::json;

static size_t sink(char* p, size_t size, size_t n, void* out) {
    static_cast<std::string*>(out)->append(p, size * n);
    return size * n;
}

// Posts JSON, returns the HTTP status and fills `reply`.
long post(const std::string& path, const json& body, json& reply) {
    CURL* c = curl_easy_init();
    std::string out, payload = body.dump();
    curl_slist* headers = curl_slist_append(nullptr, "Content-Type: application/json");
    curl_easy_setopt(c, CURLOPT_URL, ("https://sovyx-site-production.up.railway.app" + path).c_str());
    curl_easy_setopt(c, CURLOPT_HTTPHEADER, headers);
    curl_easy_setopt(c, CURLOPT_POSTFIELDS, payload.c_str());
    curl_easy_setopt(c, CURLOPT_WRITEFUNCTION, sink);
    curl_easy_setopt(c, CURLOPT_WRITEDATA, &out);
    curl_easy_perform(c);
    long status = 0;
    curl_easy_getinfo(c, CURLINFO_RESPONSE_CODE, &status);
    curl_slist_free_all(headers);
    curl_easy_cleanup(c);
    reply = json::parse(out, nullptr, false);
    return status;
}

Webhooks

Webhooks tell your own server when something happens, so you can log it, message a Discord channel or hand out a role. Add one on the Webhooks page of your dashboard (Pro and Ultimate). Choose a URL and the events you want.

Events

Check the signature

Anyone can send a request to your URL, so check that it came from Sovyx. Each webhook has its own secret (the Secret button next to it). The signature is the HMAC-SHA256 of the timestamp, a dot and the raw request body, written in hex. Compare it in constant time, and reject old timestamps so a captured request can't be replayed.

import hashlib, hmac, time
from flask import Flask, request, abort

SECRET = "paste the webhook's secret here"
app = Flask(__name__)

@app.post("/sovyx")
def sovyx():
    body = request.get_data()                      # the raw bytes, exactly as sent
    ts = request.headers.get("X-Sovyx-Timestamp", "")
    sent = request.headers.get("X-Sovyx-Signature", "")
    expected = "sha256=" + hmac.new(SECRET.encode(), ts.encode() + b"." + body, hashlib.sha256).hexdigest()
    if not hmac.compare_digest(expected, sent) or abs(time.time() - int(ts)) > 300:
        abort(400)
    event = request.get_json()
    print(event["type"], event["data"])
    return "", 204
const crypto = require("crypto");
const express = require("express");

const SECRET = "paste the webhook's secret here";
const app = express();

app.post("/sovyx", express.raw({ type: "application/json" }), (req, res) => {
  const ts = req.get("X-Sovyx-Timestamp") || "";
  const sent = req.get("X-Sovyx-Signature") || "";
  const expected = "sha256=" + crypto.createHmac("sha256", SECRET).update(ts + ".").update(req.body).digest("hex");
  const ok = sent.length === expected.length && crypto.timingSafeEqual(Buffer.from(sent), Buffer.from(expected));
  if (!ok || Math.abs(Date.now() / 1000 - Number(ts)) > 300) return res.sendStatus(400);
  const event = JSON.parse(req.body);
  console.log(event.type, event.data);
  res.sendStatus(204);
});

app.listen(3000);

Verify against the raw body, before any JSON parsing. Re-encoding the JSON can change the bytes and break the signature.

Delivery and limits

  • Reply with any 2xx status within 8 seconds. Do your real work after answering.
  • If your server is down, answers with a 5xx, 408 or 429, or times out, we try again up to 5 times in total: right away, then after 10 seconds, 1 minute, 5 minutes and 30 minutes. Other 4xx answers are not retried.
  • URLs must start with https:// and use port 443 or 8443. They must point to a public address: localhost, private networks and cloud metadata addresses are refused. Redirects are not followed.
  • Up to 25 webhooks per application. The Deliveries button shows the last results, with the host, status and number of tries.
  • Events are sent in the background and are not guaranteed. Retries wait in memory, so a Sovyx restart can drop events that are still being retried. Treat webhooks as notifications and use the API when you need an exact answer.

Use Send test to deliver a ping event to a webhook right away and see the result.

Customer pages

Every application can have a branded page at sovyx.cc/b/yourname where buyers enter a key to download your loader.

  1. Open Customer page in your dashboard and pick an address (2 to 32 lowercase letters, numbers or dashes).
  2. Set the name, tagline, accent color, background, button text, version, an optional announcement and your Discord and support links.
  3. Upload your logo (PNG, JPG, WEBP or GIF, up to 2 MB) and your loader (up to 50 MB on Free, 250 MB on paid plans). Save.

When a buyer enters a valid key the download starts. Banned or expired keys are refused, and an unused key starts its countdown. Each download link works once and expires after 5 minutes. The page also has a Reset my HWID button that follows your cooldown setting.
